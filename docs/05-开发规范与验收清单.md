# 开发规范与验收清单

## 1. 代码组织

### 1.1 命名

| 类型 | 规范 | 示例 |
|---|---|---|
| 类型 | UpperCamelCase | `FundPosition`, `StockSnapshot` |
| 属性/函数 | lowerCamelCase | `refreshAll()`, `averageCost` |
| UserDefaults Key | snake_case + 版本 | `stock_quote_cache_v1` |
| 枚举展示 rawValue | 中文可读 | `"近1月"` |

### 1.2 ViewModel

ViewModel 必须标注 `@MainActor` 并遵守：

- `@Published` 状态只在主线程更新。
- 异步刷新入口加防重入。
- 失败时保留旧状态。
- 本地持久化集中在 ViewModel 内。
- 业务计算不要写在 View 里。

```swift
if isRefreshing { return }
isRefreshing = true
defer { isRefreshing = false }
```

### 1.3 Service / Provider

网络层要求：

- ViewModel 不直接拼具体第三方接口 URL。
- 美股必须通过 `StockQuoteProviding` 抽象。
- Provider 返回标准化模型，不把上游字段泄漏到 UI。
- 捕获网络错误并映射为用户可理解的信息。

## 2. 持仓写入规范

基金以规范化后的 6 位基金代码去重。

美股以大写 symbol 去重。

规则：

- 新增时发现重复：更新已有持仓，以第二次录入为准。
- 编辑时改成另一个已存在代码/symbol：合并到已存在项，并删除被编辑项。
- 代码/symbol 变化时清理旧代码对应缓存。
- 保存后重建快照并触发刷新。

## 3. 数字格式规范

- 基金金额：人民币。
- 美股金额：美元。
- 正收益显示 `+`。
- 负收益显示 `-`。
- 百分比保留 2 位小数。
- 股数允许小数，但整数不显示 `.0`。
- 不允许无数据时显示 `$0.00` 或 `¥0.00` 来伪装真实行情。

## 4. 页面修改前检查

改 UI 前先判断影响范围：

- 是否同时影响基金和美股。
- 是否改变用户已经认可的列表信息结构。
- 是否影响输入框命中和键盘弹出。
- 是否影响底部安全区。
- 是否影响详情页编辑/取消流程。
- 是否影响横滑和点击手势冲突。

## 5. 验收清单

### 5.1 基金

- 能新增、编辑、删除基金。
- 重复添加基金时覆盖旧持仓。
- 016665 等基金获取不到估值时，应使用净值/旧数据兜底，不清空页面。
- 详情页业绩图例能区分本基金和沪深300。
- 详情页包含行情信息。
- 基金资产、当日盈亏、累计盈亏展示正确。

### 5.2 美股

- 能新增、编辑、删除 MU、TSM、NVDA、INTC、RDW、NASA 等股票。
- 重复添加股票时覆盖旧持仓。
- 搜索股票能返回候选并带入名称。
- 行情刷新失败时保留缓存。
- 当前价高于或等于成本价显示红色，低于成本价显示绿色。
- K 线区间切换优先复用缓存，不应频繁显示“暂无 K 线数据”。
- 详情页行情信息包含数据源、行情时间、本地拉取时间。

### 5.3 交互

- 顶部刷新只刷新当前 Tab。
- 频繁切 Tab 不应每次都请求网络。
- 添加/编辑页进入后快速聚焦第一输入框。
- 取消编辑不应再次弹出详情页。
- 所有全屏页左滑返回可用。
- 首页底部内容不被截断。

### 5.4 构建

常用构建命令：

```bash
xcodebuild -project FundValuationAPP.xcodeproj -scheme FundValuationApp -destination 'generic/platform=iOS' -derivedDataPath /private/tmp/FundValuationDerivedData CODE_SIGNING_ALLOWED=NO build
```

当前本地环境可能出现 simulator runtime / asset catalog 相关错误。如果没有 Swift 编译错误，通常说明代码层面已通过，但仍需在 Xcode 真机或可用模拟器中验证 UI。
