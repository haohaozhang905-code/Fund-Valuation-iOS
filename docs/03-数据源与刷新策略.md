# 数据源与刷新策略

## 1. 基金数据源

| 用途 | 来源 | 说明 |
|---|---|---|
| 实时估值 | FinMate Backend `/v1/funds/valuation/{code}` | 后端代理天天基金，返回 `gsz`、`gszzl`、`dwjz`、`jzrq`、`gztime` |
| 历史净值 | FinMate Backend `/v1/funds/nav-trend/{code}` | 后端代理东方财富 pingzhongdata，部分 QDII/T+2 可能滞后 |
| 历史净值 | FinMate Backend `/v1/funds/nav-latest/{code}` | 后端代理东方财富 F10DataApi，更及时的历史净值兜底 |
| 沪深300 | FinMate Backend `/v1/index/csi300` | 后端代理指数 K 线接口，用于详情页业绩走势对比 |

### 1.1 基金价格口径

| 时段 | currentPrice | todayBase | 当日收益口径 |
|---|---|---|---|
| 交易中 | 估值 `gsz` 优先 | 最新已公布净值 | `(gsz - latestNav) * shares` |
| 交易前/非交易日 | 最新净值 | 前一净值 | `(latest - previous) * shares` |
| 收盘后且今日净值已出 | 今日净值 | 前一净值 | `(todayNav - previous) * shares` |
| 收盘后且净值未出 | 估值 `gsz` | 同一估值响应内的 `dwjz` | 优先使用 `gszzl` |

关键约束：收盘后净值未出时，`currentPrice`、`todayBase`、`todayRate` 必须尽量来自同一估值响应，避免不同数据源混算导致跳动。

## 2. 美股数据源

美股通过 `StockQuoteProviding` 协议抽象 Provider，当前仅有一个实现：

| Provider | 用途 | 配置方式 |
|---|---|---|
| `FinMate Backend` | 唯一行情源，通过独立 FastAPI 后端桥接 Yahoo/Twelve Data/Westock 等上游 | Release 版写死，不可修改 |

### 2.1 FinMate Backend 口径

iOS 不直接请求同花顺、Yahoo、Twelve Data 或基金公开接口，而是请求独立 FinMate Backend：

```text
iOS App -> FinMate Backend -> 上游行情/基金接口 -> 标准化 JSON
```

原因：

- 上游凭证、Cookie、token、设备标识不能放在客户端。
- 上游字段变化时服务端可热修。
- Backend 可以做缓存、限流、重试、降级。
- 后续 OCR、定时任务、AI 分析也可以复用同一个后端入口。
- 已从 `StockProviderConfig` 去除了 Finnhub、Alpha Vantage、Mock 等不再维护的 Provider。

### 2.2 Stock API 合约

```http
GET /v1/stocks/search?q=MU&market=US
GET /v1/stocks/quote?symbol=MU&market=US
GET /v1/stocks/kline?symbol=MU&market=US&count=120
```

行情响应至少需要标准化为：

```json
{
  "symbol": "MU",
  "name": "Micron Technology Inc.",
  "currency": "USD",
  "regularPrice": 123.45,
  "previousClose": 120.10,
  "change": 3.35,
  "changePercent": 2.79,
  "marketState": "regular",
  "regularTimestamp": "2026-05-28T14:32:10-04:00",
  "provider": "ths",
  "providerLabel": "同花顺",
  "fetchedAt": "2026-05-28T18:32:11Z"
}
```

## 3. 后端 API 合约

### 3.1 认证

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/v1/auth/register` | 注册，返回 JWT |
| `POST` | `/v1/auth/login` | 登录，返回 JWT |
| `POST` | `/v1/auth/password-reset/request` | 请求重置验证码（SMTP 邮件或日志） |
| `POST` | `/v1/auth/password-reset/confirm` | 验证码 + 新密码，重置成功返回 JWT |
| `POST` | `/v1/auth/logout` | 登出 |
| `DELETE` | `/v1/account` | 注销账号（软删除 + 清空持仓） |

### 3.2 持仓

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/v1/portfolio` | 获取当前用户持仓 |
| `PUT` | `/v1/portfolio` | 原子替换持仓（去重校验） |

### 3.3 健康检查

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/health` | 返回 `{"status":"ok","fetchedAt":"..."}` |
| `GET` | `/openapi.json` | FastAPI 生成的三端共享 OpenAPI 合约 |

## 4. 刷新策略

### 4.1 触发时机

| 触发 | 基金 | 美股 |
|---|---:|---:|
| App 首次启动 | 刷新当前 Tab | 刷新当前 Tab |
| 下拉刷新 | 强制刷新 | 强制刷新 |
| 顶部刷新按钮 | 强制刷新当前 Tab | 强制刷新当前 Tab |
| 从后台回前台 | 强制刷新当前 Tab | 强制刷新当前 Tab |
| 停留在当前 Tab | 5 分钟 | 60 秒 |
| 频繁切 Tab | 5 分钟内不重复刷 | 30 秒内不重复刷 |

### 4.2 失败兜底

基金：

- 单只基金失败：保留旧快照。
- 全部基金失败：不覆盖旧列表。
- 交易日估值失败：重试后仍失败，当日收益按 0 或旧数据策略处理，不混用不一致数据源。

美股：

- 单只股票失败：优先使用 `stock_quote_cache_v1`。
- 无缓存：展示空快照和错误说明。
- 全部失败：保留旧数据并显示"行情刷新失败，显示上次数据"。
- K 线失败：优先使用已有缓存；区间切换时可从更长区间裁剪出较短区间。

## 5. 缓存策略

| Key | 内容 |
|---|---|
| `fund_list` | 基金持仓 |
| `intraday_pct_cache_v1` | 基金日内走势缓存 |
| `ai_config_v1` | AI 配置 |
| `ai_auto_enabled` | AI 自动分析开关 |
| `ai_auto_trigger_cache_v1` | AI 自动触发去重 |
| `stock_positions_v1` | 美股持仓 |
| `stock_quote_cache_v1` | 美股行情缓存 |
| `stock_provider_config_v1` | 美股 Provider 配置（仅保留 apiKey） |
| `stock_sort_field_v1` | 美股排序字段 |
| `stock_sort_order_v1` | 美股排序方向 |
| `stock_kline_cache_v1` | 美股 K 线缓存 |
| `fund_theme` | 主题设置 |
| `auth_email` | 上次登录邮箱（恢复会话用） |
| `auth_user_id` | 上次登录用户 ID（恢复会话用） |

Token 存储在系统 Keychain，服务名 `FinMate.Auth`，不通过 UserDefaults 存储。

## 6. 重试规范

所有直接影响页面渲染的数据请求都需要具备重试或缓存兜底：

- 搜索：失败后返回空结果，并给出状态消息。
- 行情：至少重试 2 次，失败后用缓存。
- K 线：优先缓存，网络失败后回退缓存。
- 基金估值：交易时段重试，失败后保留旧数据。
- 认证请求（注册/登录）：全局超时 8 秒。
- 持仓同步（bootstrap）：独立 5 秒超时，网络错误静默。

不要让网络失败导致页面空白、列表清空或价格变成 0。
