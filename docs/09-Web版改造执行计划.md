# Web 版改造执行计划

## 1. 目标

将现有纯前端单页应用（`Fund-Valuation-Viewing`）改造为 iOS 端的网页分身，共享同一套后端服务，实现：

- 同一账号、同一持仓数据，手机和网页实时同步
- 网页端覆盖 iOS 端全部核心功能（基金 + 美股持仓查看与管理）
- 后端 100% 复用，不改动现有 iOS 后端 API

---

## 2. 可复用资源

### 2.1 后端（完全复用）

| 接口 | 用途 | 当前状态 |
|------|------|---------|
| `POST /v1/auth/register` | 注册 | ✅ 已在 Zeabur 运行 |
| `POST /v1/auth/login` | 登录 | ✅ |
| `POST /v1/auth/password-reset/*` | 找回密码 | ✅ |
| `DELETE /v1/account` | 注销账号 | ✅ |
| `GET /v1/portfolio` | 获取持仓 | ✅ |
| `PUT /v1/portfolio` | 上传持仓 | ✅ |
| `GET /v1/stocks/quote` | 美股行情 | ✅ |
| `GET /v1/stocks/search` | 美股搜索 | ✅ |
| `GET /v1/stocks/kline` | 美股 K 线 | ✅ |
| `GET /health` | 健康检查 | ✅ |

### 2.2 基金行情数据（保持前端直连）

基金估值和净值仍由前端直接请求天天基金/东方财富接口，与 iOS 端一致，不走后端。原因：
- 这些接口是公开的 JSONP，前端可直接调用
- 走后端会增加延迟和后端负载

### 2.3 设计语言

iOS 端视觉规范（深色主题、圆角风格）可直接复用到网页端：

| 元素 | iOS 色值 | 对应 CSS |
|-----|---------|---------|
| 页面背景 | `0x1C1C1E` | `--bg: #1c1c1e` |
| 卡片背景 | `0x0A0A0A` | `--card: #0a0a0a` |
| 强调色 | `0x2B7FFF` | `--accent: #2b7fff` |
| 涨 | 红色 | `--red: #ff3b30` |
| 跌 | 绿色 | `--green: #34c759` |
| 圆角 | 14-18px | `--radius: 14px` |

## 3. 改造范围

保持单 HTML 文件可用的原则不变，但按模块拆分为三个文件便于维护。

### 3.2 核心改动

#### Phase 1：接入登录（2 天）

| 改动 | 说明 |
|------|------|
| 新增登录/注册 UI | 模态弹窗，邮箱 + 密码 + 确认密码 |
| JWT 存储 | `localStorage` 存储 access token |
| 启动时验证 | 页面加载时用 `GET /v1/auth/me` 验证 token 有效性 |
| 登出 | 清除 token，回到登录页 |
| 登录状态持久化 | 刷新页面后自动恢复（类似 iOS Keychain） |

**登录页 UI 设计参考**：深色背景、居中卡片、邮箱输入、密码输入、登录/注册切换、找回密码链接，风格与 iOS AuthViews 一致。

#### Phase 2：持仓同步（2 天）

| 改动 | 说明 |
|------|------|
| 启动时拉取远程持仓 | `GET /v1/portfolio`，合并或覆盖本地数据 |
| 增/删/改时同步 | 每次操作后调用 `PUT /v1/portfolio` |
| 批量导入脚本 | 复用 `ths-bridge/batch_import.py` |
| 同步冲突处理 | 远程优先（覆盖本地） |

**数据流**：
```
页面加载 → 验证 token → GET /v1/portfolio → 回填页面
用户操作 → 更新页面 → PUT /v1/portfolio → 同步到云端
```

| 美股列表 | 与基金列表并列，分段 Tab 切换 |

## 5. 技术方案

### 5.1 架构

```text
浏览器
  ├── 登录/注册 → POST /v1/auth/login → JWT → localStorage
  ├── 基金持仓 → 天天基金 API（直连）+ 本地计算
  ├── 美股持仓 → POST /v1/stocks/quote（走后端）
  └── 持仓同步 → GET|PUT /v1/portfolio（走后端）
```

### 5.2 开发方式

- **保持单文件可用性**：核心逻辑写在 `app.js` 中，不引入前端框架
- **逐步改造**：在现有 index.html 基础上增加新功能，不重写
- **兼容设计**：页面宽度自适应，手机和桌面都能用
- **GitHub Pages 部署**：保持当前部署方式不变

### 5.3 与 iOS 端的差异

| 方面 | iOS | Web |
|------|-----|-----|
| 框架 | SwiftUI | 原生 JS |
| 状态管理 | ViewModel + @Published | 全局 JS 对象 + DOM 更新 |
| 数据持久化 | Keychain + UserDefaults | localStorage |
| 行情来源 | 基金直连、美股走后端 | 基金直连、美股走后端 |
| 部署 | App Store / TestFlight | GitHub Pages |

## 7. 风险与注意事项

1. **CORS**：当前后端未配置 CORS，前端浏览器跨域请求会被拦截。需要在 `app.py` 中添加 `CORSMiddleware` 允许来自 GitHub Pages 的请求。
2. **Token 安全**：JWT 存储在 `localStorage`，存在 XSS 泄露风险。个人使用可接受，如需更高安全应使用 `httpOnly Cookie`。
3. **浏览器兼容**：需兼容 Chrome/Safari/Firefox 最新两个大版本。
4. **基金接口跨域**：天天基金和东方财富的 JSONP 接口不受 CORS 限制，保持现有方式即可。
5. **数据一致性**：iOS 和 Web 同时使用时，后同步的一方会覆盖先前的数据（最后写入胜出）。
