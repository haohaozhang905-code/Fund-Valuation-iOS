# 架构与模块规范

## 1. 总体架构

项目使用 SwiftUI + MVVM。View 负责界面和交互，ViewModel 负责状态、持久化、刷新和收益计算，Service 负责网络接口和数据解析，Model 负责可持久化或可渲染的数据结构。

```text
SwiftUI View
  -> ViewModel (@MainActor ObservableObject)
    -> Service / Provider
      -> FinMate Backend (/v1/*)
    -> UserDefaults / Keychain
    -> Portfolio Sync API
```

后端已从本 iOS 仓库拆分到独立项目：

```text
/Users/billzhang/GitHub/Fund Valuation Backend
```

iOS、Web 和未来 Android 共用该后端的账号体系、云端持仓表和行情代理 API。

## 3. 认证模块设计

### 3.1 认证流程

```text
RootView
  ├── 未登录 → AuthFlowView (登录/注册/找回密码)
  │     └── SessionViewModel.register/login()
  │           └── AuthService → POST /v1/auth/register|login
  │                 └── 后端验证 → 返回 JWT
  │                       └── SessionViewModel.persist() → Keychain + UserDefaults
  └── 已登录 → MainView
        └── SessionViewModel.bootstrapPortfolio()
              ├── GET /v1/portfolio → 远程有持仓
              │     └── 同步到本地
              └── 本地有持仓 → PUT /v1/portfolio 上传
```

### 3.2 关键决策

- Token 存储在 Keychain（系统级安全存储），不清除 App 数据则不会丢失。
- Registration/Login 成功后自动保存 token 到 Keychain + UserDefaults，下次启动自动恢复。
- 找回密码：后端生成 6 位数字验证码 → SHA-256 哈希存储 → SMTP 发送邮件 → 10 分钟过期 → 5 次尝试限制。
- 后端地址：Release 构建写死 `https://thsbridge.zeabur.app`，不暴露给用户；该域名由独立 FinMate Backend 项目提供。
- 持仓同步失败时保留本地缓存，不清除用户数据。

## 4. 模块边界

### 4.1 基金模块

基金模块只处理场外基金：

- 以基金代码为唯一业务键。
- 当前价格是估值或净值。
- 收益按单位净值变化乘以份额计算。
- 走势对比基准是沪深300。
- AI 分析当前仅面向基金组合。

基金逻辑不要依赖 `StockViewModel` 或美股 Provider。

### 4.2 美股模块

美股模块只处理 US 股票持仓：

- 以股票 symbol 为唯一业务键。
- 主价格使用 regular price。
- 当日盈亏基于 `regularPrice - previousClose`。
- 累计盈亏基于 `regularPrice - averageCost`。
- 盘前/盘后数据只作为行情补充，不覆盖主收益口径。
- 行情数据源固定为 FinMate Backend，不可切换。

股票逻辑不要写进 `FundViewModel`。

### 4.3 MainView 边界

`MainView` 可以组合基金和美股页面，但不应该承载美股业务计算。新增股票能力时优先放入：

- Model -> `StockModels.swift`
- Provider / API -> `StockServices.swift`
- 状态和计算 -> `StockViewModel.swift`
- UI -> `StockViews.swift`

### 4.4 认证模块边界

`AuthViews` 只负责 UI 展示，不处理业务逻辑。
`SessionViewModel` 管理会话状态，不持有 UI 引用。
`AuthService` 只负责 HTTP 通信，无状态设计。
`KeychainStore` 为静态工具类，不实例化。

## 5. 导航规范

当前主要使用 `fullScreenCover` 打开详情、编辑、设置和 AI 页面。所有全屏页需要：

- 自己提供顶部导航。
- 支持取消/返回。
- 支持左侧边缘右滑返回。
- 进入编辑页时带入历史数据。
- 取消编辑后回到原页面状态，不二次弹出详情页。

## 6. Tab 切换规范

基金/美股是资产类型切换，不是底部 Tab Bar。顶部使用分段控件。

当前实现使用垂直 `ScrollView` 承载内容，并通过横向拖拽切换 `selectedTab`。后续如果重新做页面级横滑，需要优先验证：

- 不裁剪底部内容。
- 不和列表点击冲突。
- 横滑时页面整体移动。
- 点击顶部 Tab 和横滑动画一致。

不要在没有真机验证的情况下再次引入会裁剪页面高度的分页容器。
