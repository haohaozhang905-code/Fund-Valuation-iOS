# 数据源与刷新策略

## 1. 基金数据源

| 用途 | 来源 | 说明 |
|---|---|---|
| 实时估值 | 天天基金 `fundgz.1234567.com.cn/js/{code}.js` | 返回 `gsz`、`gszzl`、`dwjz`、`jzrq`、`gztime` |
| 历史净值 | 东方财富 `fund.eastmoney.com/pingzhongdata/{code}.js` | `Data_netWorthTrend`，部分 QDII/T+2 可能滞后 |
| 历史净值 | 东方财富 F10DataApi | 更及时的历史净值兜底 |
| 沪深300 | 新浪/东方财富指数 K 线接口 | 用于详情页业绩走势对比 |

### 1.1 基金价格口径

| 时段 | currentPrice | todayBase | 当日收益口径 |
|---|---|---|---|
| 交易中 | 估值 `gsz` 优先 | 最新已公布净值 | `(gsz - latestNav) * shares` |
| 交易前/非交易日 | 最新净值 | 前一净值 | `(latest - previous) * shares` |
| 收盘后且今日净值已出 | 今日净值 | 前一净值 | `(todayNav - previous) * shares` |
| 收盘后且净值未出 | 估值 `gsz` | 同一估值响应内的 `dwjz` | 优先使用 `gszzl` |

关键约束：收盘后净值未出时，`currentPrice`、`todayBase`、`todayRate` 必须尽量来自同一估值响应，避免不同数据源混算导致跳动。

## 2. 美股数据源

美股通过 `StockQuoteProviding` 抽象 Provider。当前支持：

| Provider | 用途 | 配置 |
|---|---|---|
| `THS Bridge` | 推荐主源，适合接同花顺/Westock/自建上游 | Bridge URL；Access Token 可选 |
| `Finnhub` | 备用行情源 | API Key |
| `Alpha Vantage` | 低频兜底和验证 | API Key |
| `Mock` | 本地 UI/交互调试 | 无 |

### 2.1 THS Bridge 口径

iOS 不直接请求同花顺底层接口，而是请求自建 Bridge：

```text
iOS App -> THS Bridge -> 同花顺/Westock/其他上游 -> 标准化 JSON
```

原因：

- 上游凭证、Cookie、token、设备标识不能放在客户端。
- 上游字段变化时服务端可热修。
- Bridge 可以做缓存、限流、重试、降级。
- 后续 OCR、定时任务、AI 分析也可以复用同一个后端入口。

### 2.2 Bridge API 合约

```http
GET /v1/stocks/search?q=MU&market=US
GET /v1/stocks/quote?symbol=MU&market=US
GET /v1/stocks/kline?symbol=MU&market=US&count=120
```

行情响应至少需要标准化为：

```json
{
  "symbol": "MU",
  "name": "Micron Technology Inc.",
  "currency": "USD",
  "regularPrice": 123.45,
  "previousClose": 120.10,
  "change": 3.35,
  "changePercent": 2.79,
  "marketState": "regular",
  "regularTimestamp": "2026-05-28T14:32:10-04:00",
  "provider": "ths",
  "providerLabel": "同花顺",
  "fetchedAt": "2026-05-28T18:32:11Z"
}
```

## 3. 刷新策略

### 3.1 触发时机

| 触发 | 基金 | 美股 |
|---|---:|---:|
| App 首次启动 | 刷新当前 Tab | 刷新当前 Tab |
| 下拉刷新 | 强制刷新 | 强制刷新 |
| 顶部刷新按钮 | 强制刷新当前 Tab | 强制刷新当前 Tab |
| 从后台回前台 | 强制刷新当前 Tab | 强制刷新当前 Tab |
| 停留在当前 Tab | 5 分钟 | 60 秒 |
| 频繁切 Tab | 5 分钟内不重复刷 | 30 秒内不重复刷 |

### 3.2 失败兜底

基金：

- 单只基金失败：保留旧快照。
- 全部基金失败：不覆盖旧列表。
- 交易日估值失败：重试后仍失败，当日收益按 0 或旧数据策略处理，不混用不一致数据源。

美股：

- 单只股票失败：优先使用 `stock_quote_cache_v1`。
- 无缓存：展示空快照和错误说明。
- 全部失败：保留旧数据并显示“行情刷新失败，显示上次数据”。
- K 线失败：优先使用已有缓存；区间切换时可从更长区间裁剪出较短区间。

## 5. 重试规范

所有直接影响页面渲染的数据请求都需要具备重试或缓存兜底：

- 搜索：失败后返回空结果，并给出状态消息。
- 行情：至少重试 2 次，失败后用缓存。
- K 线：优先缓存，网络失败后回退缓存。
- 基金估值：交易时段重试，失败后保留旧数据。

不要让网络失败导致页面空白、列表清空或价格变成 0。
