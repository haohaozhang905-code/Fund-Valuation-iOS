# UI 交互与视觉规范

## 1. 总体方向

当前 App 是高频金融工具，不是营销页面。视觉目标是清楚、稳定、扫读效率高。

明确不做：

- 液态玻璃风格。
- 大面积模糊、半透明、泛灰玻璃层。
- 股票头像/logo。
- 大面积蓝色按钮或渐变背景。
- 改动基金和美股列表的信息结构。

## 2. 基础视觉变量

当前基准色来自 `AppVisual` 和 `StockVisual`：

| 用途 | 色值 |
|---|---|
| 页面背景 | `0x1C1C1E` |
| 顶部栏/卡片 | `0x0A0A0A` |
| 二级背景/选中态 | `0x2C2C2E` |
| 分割线 | `0x262626` 低透明度 |
| 辅助文字 | `0xA1A1A1` |
| 基金线/弱强调 | `0x2B7FFF` |
| 沪深300线 | `0xFF9500` |
| 涨/盈利 | 红色 |
| 跌/亏损 | 绿色 |

后续视觉调整必须保持红绿只服务于涨跌，不把红绿用作装饰色。

## 3. Banner 规范

基金和美股 Banner 必须保持同构：

```text
┌────────────────────────────────────┐
│ 基金资产/美股资产            交易中 │
│ ¥ / $ 总资产                        │
│                                    │
│ 当日盈亏          │ 累计盈亏         │
│ 金额 + 比例       │ 金额 + 比例      │
│                                    │
│ 行情更新/数据说明              +    │
└────────────────────────────────────┘
```

要求：

- 标题、状态标签、总资产、两列盈亏、竖线、底部小字、添加按钮的位置在基金和美股中一致。
- 添加按钮放在 Banner 右下角，视觉低强调，优先使用单独加号。
- 状态文案统一：`交易中`、`休市`、`盘前`、`盘后`、`--`。
- 基金不要叫“账户总资产”，统一叫“基金资产”。
- 美股叫“美股资产”。

## 4. 列表规范

基金列表和美股列表的内容结构已基本确定，视觉优化不应随意改字段。

基金列表：

- 左侧：基金名称、市值/份额等辅助信息。
- 右侧：当日盈亏、累计盈亏。

美股列表：

- 左侧：股票代码/名称、现价/成本价、股数、市值、更新时间。
- 右侧：当日盈亏、累计盈亏。
- 当日盈亏比例放在当日盈亏金额下方。
- 现价相对成本价：高于或等于成本价显示红色，低于成本价显示绿色。
- 股数展示要兼容小数，但整数不要展示成 `1.0`。

## 5. 详情页规范

基金详情页：

- 顶部展示基金代码、名称、状态。
- 主要展示当日盈亏/涨跌、当前净值/估值。
- 明细网格展示持有金额、份额、成本、累计收益等。
- 业绩走势必须显示图例：本基金和沪深300，颜色与图线一致。
- 补充“行情信息”，至少包含数据日期、估值/净值时间、数据口径。

美股详情页：

- 顶部展示 symbol、名称、市场状态。
- 今日涨跌文案统一为“价格变动”，金额和比例需要有主次层级。
- 明细网格展示现价、成本价、股数、市值、当日盈亏、累计盈亏。
- K 线区间和基金区间尽量统一：近7日、近1月、近3月、近6月、近1年、近3年。
- 行情信息展示数据源、行情时间、本地拉取时间、是否旧数据。

## 6. 表单交互

添加/编辑基金和股票都需要：

- 进入后默认聚焦第一个输入框并尽快弹出键盘。
- 点击输入框命中区域足够大。
- 编辑时带入历史数据。
- 保存后刷新对应资产。
- 取消后只关闭当前编辑页，不二次弹出详情页。
- 重复添加时以第二次为准，并提示已覆盖。

## 7. 页面交互

- 所有全屏页面支持左侧边缘右滑返回。
- 页面跳转动画要统一，不要一部分动画、一部分无动画。
- 横向切换 Tab 时优先保证不误触列表项。
- 不显示亮色滚动条。
- 页面底部不能被容器裁剪，内容应能自然滚动到底部并留出安全区和悬浮按钮空间。

## 8. 圆角规范

| 组件 | 建议 |
|---|---|
| 首页 Banner | 20 |
| 列表容器 | 18 |
| 输入框 | 14 |
| 搜索结果/行内高亮 | 14 |
| Tab 容器 | 14 |
| Tab 选中态 | 10 |
| 小标签 | 6 |
| 圆形图标按钮 | Circle |

后续新增 UI 先复用现有圆角，不新增一套随机半径。
